# Transpiler Reference

The transpiler accepts three lists as input:
```python
phys_channels: list[str], 
virt_labels: list[str], 
virt_formulas: list[str]
```

If a remote system was configured to sample the following data in order:
 - Channel `T_amb` from location `cDAQ1Mod1/ai0`
 - Channel `T_surf` from location `cDAQ1Mod1/ai3`
 - Channel `T_fluid` from location `cDAQ1Mod1/ai2`

Then each call of DAQmx's Analog Read Nchan 1samp block would yield a 3-item double array, corresponding to the values [`T_amb`, `T_surf`, `T_fluid`]. As such, the transpiler should be given the list for `phys_channels` in the same order: [`T_amb`, `T_surf`, `T_fluid`].

If the user wanted the following virtual signals to be calculated per-sample:
 - Channel `T_mean = (T_amb + T_surf + T_fluid) / 3`
 - Channel `T_max = T_surf if T_surf >= T_fluid else T_fluid`

Then the list of virtual labels [`T_mean`, `T_max`] and virtual formulas [`(T_amb + T_surf + T_fluid) / 3`, `T_surf if T_surf >= T_fluid else T_fluid`] should match orders.

Passing those arguments into the transpiler, by calling:
```python
generate_c_library(
    phys_channels = ["T_amb", "T_surf", "T_fluid"], 
    virt_labels = ["T_mean", "T_max"], 
    virt_formulas = ["(T_amb + T_surf + T_fluid) / 3",
        "T_surf if T_surf >= T_fluid else T_fluid"]
)
```

would return the following C code:

```c
// Generated by main.py ({Path to transpiler}, {Time of transpilation})

#include <math.h>

void evaluate_channels (const double* __restrict__ phys, double* __restrict__ virt) {

        // T_mean = (T_amb + T_surf + T_fluid) / 3
        virt[0] = ((3.0) != 0.0 ? (((phys[0] + phys[1]) + phys[2])) / (3.0) : 0.0);

        // T_max = T_surf if T_surf >= T_fluid else T_fluid
        virt[1] = ((phys[1] >= phys[2]) ? phys[1] : phys[2]);

}

// End of generated code
```

The generated code contains a double array re-assignment for each of the specified virtual channels. This necessitates that the array is reserved ahead of time. Each re-assignment has a comment with the original string, and an ERROR if the transpiler failed to evaluate the original string.

We can see some interesting outputs: Any division incurs a check for zeros, since we are not using safe division on the RT target. For the example above, `3.0` will never be equal to `0.0`, so the compiler will strip away the check and statically evaluate the `True` option. This is lazy on the transpiler's behalf, which should evaluate such expressions and exclude redundant checks. We can also see that Python's inline `if else` syntax is converted to inline `C` evaluations, allowing for more complex functions to be written.

The configuration code is available in [main.py](/src/main.py), and the output is in [main.c](/src/main.c). When compiled and run, main.c prints:
```
[80.50, 82.50]
```
