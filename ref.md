# Transpiler Reference (`lvCompHelper`)

`lvCompHelper` transpiles Python mathematical expressions and control structures into optimized, platform-agnostic C code designed for high-frequency execution (e.g., >1 kHz) on National Instruments Real-Time targets (such as CompactDAQ running NI Linux Real-Time).

---

## 1. Top-Level Transpiler Interface

The primary entry point is `generate_c_library`, defined in [`src/lvchAST.py`](/src/lvchAST.py):

```python
def generate_c_library(
    phys_channels: list[str], 
    virt_labels: list[str], 
    virt_formulas: list[str], 
    tab_spaces: int = 0, 
    debug: bool = False
) -> str
```

### Parameters
* `phys_channels` (`list[str]`): Ordered labels representing input channels read from hardware (e.g., via DAQmx Analog Read NChan 1Samp).
* `virt_labels` (`list[str]`): User-defined labels for output virtual channels.
* `virt_formulas` (`list[str]`): Mathematical formulas in Python syntax corresponding 1-to-1 with `virt_labels`.
* `tab_spaces` (`int`, optional): Number of spaces used for indentation. Defaults to `0` (uses standard tabs `\t`).
* `debug` (`bool`, optional): Enables compile-time size macros, safety NULL pointer checks, and an automated register inspection utility (`print_registers`). Defaults to `False`.

### Return Value
* `str`: A self-contained C source code string ready to be compiled into a shared library (`.so`).

## 2. Basic Example: Physical Inputs & Virtual Outputs

Consider an NI cDAQ module configured to sample three temperature channels:
* Channel `T_amb` at `cDAQ1Mod1/ai0`
* Channel `T_surf` at `cDAQ1Mod1/ai3`
* Channel `T_fluid` at `cDAQ1Mod1/ai2`

Each DAQmx Read call yields a 3-element double array: `[T_amb, T_surf, T_fluid]`. The transpiler maps these sequentially to `phys[0]`, `phys[1]`, and `phys[2]`.

To compute:
* `T_mean = (T_amb + T_surf + T_fluid) / 3`
* `T_max = T_surf if T_surf >= T_fluid else T_fluid`

Call the transpiler:
```python
from lvchAST import generate_c_library

code = generate_c_library(
    phys_channels = ["T_amb", "T_surf", "T_fluid"], 
    virt_labels = ["T_mean", "T_max"], 
    virt_formulas = [
        "(T_amb + T_surf + T_fluid) / 3",
        "T_surf if T_surf >= T_fluid else T_fluid"
    ]
)
```

### Generated C Code (`debug=False`)
```c
// Generated by main.py ({Transpiler path}, {Transpilation time})


#include <stdint.h>

// Registers

int32_t get_physical_register_count() {
	return 3;
}
int32_t get_virtual_register_count() {
	return 2;
}
int32_t get_transient_register_count() {
	return 0;
}
// End registers

int evaluate_channels (const double* phys, double* virt, double* trans) {

	// T_mean = (T_amb + T_surf + T_fluid) / 3
	virt[0] = (((phys[0] + phys[1]) + phys[2])) * (0.3333333333333333);

	// T_max = T_surf if T_surf >= T_fluid else T_fluid
	virt[1] = ((phys[1] >= phys[2]) ? phys[1] : phys[2]);

	return 0;
}

// End of generated code
```

## 3. Exported C Interface

Every generated library exports a standardized, C-compatible ABI consisting of register query helpers and the main evaluation loop.

### 1. `evaluate_channels`
```c
int evaluate_channels (const double* phys, double* virt, double* trans);
```
* **`phys` (`const double*`):** Pointer to the input buffer of physical channels.
* **`virt` (`double*`):** Pointer to the pre-allocated output buffer where virtual channel results are stored.
* **`trans` (`double*`):** Pointer to the pre-allocated transient state buffer maintaining state across loop iterations.
* **Return Code (`int`):** Returns `0` on success. In `debug` mode, returns `1` if any pointer (`phys`, `virt`, or `trans`) is `NULL`.

### 2. Register Query Helpers
```c
int32_t get_physical_register_count();
int32_t get_virtual_register_count();
int32_t get_transient_register_count();
```
These functions allow the host application (LabVIEW or C harness) to query buffer size requirements during setup.

## 4. Stateful & Transient Functions

When formulas involve stateful operations (controllers, filters, timers), `lvchAST` automatically allocates slots in `trans` and injects their C definitions. To view all available functions at runtime, call `get_functions() -> list[str]`. The following functions all have hidden state and should try to be used sparingly.

| Function | Python Signature | Purpose / Behavior |
| :--- | :--- | :--- |
| **PID** | `PID(pv, sp, gain_p, gain_d, gain_i)` | Gain-based PID controller. Suppresses initial derivative kick on tick 1. |
| **PIDa** | `PIDa(pv, sp, gain_p, gain_d, gain_i, wu_err, out_lo, out_hi)` | 3 (`last_pv`, `acc_err`, `init`) | Advanced PID with anti-windup clamping and output saturation. |
| **EMA** | `EMA(x, alpha)` | Exponential moving average (IIR low-pass filter). $0 < \alpha \le 1$. |
| **slew_limit** | `slew_limit(pv, rate)` | Limits the maximum rate of change per tick to $\pm\text{rate}$. |
| **elapsed** | `elapsed()` | Monotonic time in seconds since the first execution tick. |
| **time_delta** | `time_delta()` | Monotonic time delta in seconds between the current and previous tick. |
| **delta** | `delta(x)` | Difference $\Delta x = x_k - x_{k-1}$ between the current and previous tick. |
| **derivative** | `derivative(y, x)` | Discrete rate of change $\frac{\Delta y}{\Delta x}$. |

_This reference is likely already out-of-date. Refer to `lvchAST`'s `def get_functions() -> list[str]` to get a list of strings containing signatures and a docstring._

## 5. Topological Sorting & Channel Inter-Dependencies

Formulas can freely reference other virtual channels by name. `lvchAST` resolves the dependency graph and evaluates equations in valid topological order.

```python
code = generate_c_library(
    phys_channels = ["ch_0", "ch_1", "ch_2"], 
    virt_labels = ["vch_0", "vch_1", "vch_2"], 
    virt_formulas = [
        "vch_2 + 3 / 4",
        "ch_0 + PID(ch_1, ch_2, 10, 1, 0.01)",
        "fmax(elapsed() - 1, 0)"
    ]
)
```

Notice below that `vch_2` is evaluated before `vch_0` because `vch_0` references `vch_2`:

```c
// Generated by main.py ({Transpiler path}, {Transpilation time})

#ifndef _POSIX_C_SOURCE
#define _POSIX_C_SOURCE 199309L
#endif

#include <time.h>
#include <math.h>
#include <stdint.h>

// Generated dependencies

double PID(double pv, double sp, double gain_p, double gain_d, double gain_i, double* last_pv, double* acc_err, double* init) {
	
	// PID Controller
	// Uses pure gains (not times)
	
	double p_err = sp - pv;       // Proportional error
	double d_err = *last_pv - pv; // Derivative error
	*acc_err += p_err;            // Integral error
	*last_pv = pv;                // Proc var
	
	double cmd = gain_p * p_err + *init * (gain_d * d_err + gain_i * *acc_err);
	*init = 1.0;
	
	return cmd;
	
}

double elapsed(double* start_s, double* start_ns) {
	
	// Elapsed time in seconds
	
	struct timespec now;
	clock_gettime(CLOCK_MONOTONIC, &now);
	
	if (*start_s == 0.0) {
	*start_s  = (double)now.tv_sec;
	*start_ns = (double)now.tv_nsec;
	return 0.0;
	}
	
	double total_elapsed = (now.tv_sec - *start_s) + (now.tv_nsec - *start_ns) * 1e-9;
	return total_elapsed;
	
}

// End generated dependencies

// Registers

int32_t get_physical_register_count() {
	return 3;
}
int32_t get_virtual_register_count() {
	return 3;
}
int32_t get_transient_register_count() {
	return 5;
}
// End registers

int evaluate_channels (const double* phys, double* virt, double* trans) {

	// vch_2 = fmax(elapsed() - 1, 0)
	virt[2] = fmax((elapsed(&trans[3], &trans[4]) - 1.0), 0.0);

	// vch_1 = ch_0 + PID(ch_1, ch_2, 10, 1, 0.01)
	virt[1] = (phys[0] + PID(phys[1], phys[2], 10.0, 1.0, 0.01, &trans[0], &trans[1], &trans[2]));

	// vch_0 = vch_2 + 3 / 4
	virt[0] = (virt[2] + 0.75);

	return 0;
}

// End of generated code
```

If a circular dependency is introduced (e.g., `A` depends on `B` and `B` depends on `A`), `generate_c_library` captures the `CycleError` and returns an error stub with an empty `evaluate_channels`, preventing unsafe compilation.

## 6. Division Safety & Optimization

The transpiler handles division with two distinct optimizations:
1. **Constant Inversion:** When dividing by a non-zero literal constant (e.g., `/ 3` or `3 / 4`), the division is converted into multiplication by the reciprocal (e.g., `* (0.3333333333333333)` or `0.75`), which is likely optimized away at -O3 anyways but a cool gimmick.
2. **Safe Division (`_safe_divide`):** When dividing by dynamic channels or expressions where the divisor is liable to be zero, a zero-checked helper function is automatically generated:

```python
code = generate_c_library(
    phys_channels = ["ch_0", "ch_1"], 
    virt_labels = ["vch_0"], 
    virt_formulas = ["ch_0 / ch_1"]
)
```

```c
// Generated by main.py ({Transpiler path}, {Transpilation time})


#include <stdint.h>

// Generated dependencies

double _safe_divide(double x, double y) {
	
	// Zero-checked division
	
	return y != 0.0 ? x / y : 0.0;
	
}

// End generated dependencies

// Registers

int32_t get_physical_register_count() {
	return 2;
}
int32_t get_virtual_register_count() {
	return 1;
}
int32_t get_transient_register_count() {
	return 0;
}
// End registers

int evaluate_channels (const double* phys, double* virt, double* trans) {

	// vch_0 = ch_0 / ch_1
	virt[0] = _safe_divide(phys[0], phys[1]);

	return 0;
}

// End of generated code
```

## 7. Debug Mode (`debug=True`)

Setting `debug=True` provides several diagnostic utilities:
1. **Preprocessor Size Definitions:** Emits `#define LVCH_GET_PHYSICAL_REGISTER_COUNT`, `LVCH_GET_VIRTUAL_REGISTER_COUNT`, and `LVCH_GET_TRANSIENT_REGISTER_COUNT` to easily size static arrays in standalone C test harnesses.
2. **Defensive Pointer Validation:** Injects `if (!phys || !virt || !trans) { return 1; }` into `evaluate_channels()` to safely prevent segmentation faults if uninitialized or `NULL` arrays are passed from LabVIEW.
3. **Automated Register Inspection Tool:** Automatically generates `static void print_registers(double* phys, double* virt, double* trans)` using `printf` to display all physical channels, virtual channels, and labeled transient registers (e.g. `PID:acc_err`, `elapsed:start_s`) with 6 decimal places.

```python
code = generate_c_library(
    phys_channels = ["ch_0", "ch_1", "ch_2"], 
    virt_labels = ["vch_0", "vch_1", "vch_2"], 
    virt_formulas = [
        "vch_2 + 3 / 4",
        "ch_0 + PID(ch_1, ch_2, 10, 1, 0.01)",
        "fmax(elapsed() - 1, 0)"
    ],
    debug = True
)
```

## 8. Integration with NI LabVIEW & RT Targets

When deploying the generated library on an NI Real-Time target via LabVIEW's **Call Library Function Node (CLFN)**, the following must be observed:

1. **Calling Convention:** Set to **C** (not `stdcall`).
2. **Parameter Format:**
   * Parameter `phys`: Type = `Array`, Data Type = `8-Byte Double`, Array Format = **`Array Data Pointer`**
   * Parameter `virt`: Type = `Array`, Data Type = `8-Byte Double`, Array Format = **`Array Data Pointer`**
   * Parameter `trans`: Type = `Array`, Data Type = `8-Byte Double`, Array Format = **`Array Data Pointer`**
   > Using `Array Handle` will feed bad data in and I believe segfault. The generated C code operates directly on standard floating point pointers (`double*`).
3. **Transient Memory Allocation:**
   * Call `get_transient_register_count()` during setup
   * Allocate `trans` using `Initialize Array` (`element = 0.0`, `dimension size = count`)
   * Pass `trans` through an **initialized Shift Register** across the loop, ensuring the right-hand output terminal of the CLFN is wired back into the right shift register
4. **Compilation on Remote Target:**
   Compile the generated code on the target via GCC:
   ```bash
   gcc -shared -fPIC -O3 -o libevaluate.so evaluate.c
   ```
